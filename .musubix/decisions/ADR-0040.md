# ADR-0040: Bound the ordinary full-test ceiling

Status: Accepted for Generation 27; Generation 45 supersession pending design approval.

## Context

CHANGE-0017 Generation 19 completed valid Git LFS Red/Green chronology, but the
configured ordinary full-test command remained limited to 180000 ms. The user
explicitly changed that release policy before quality to a limit below 300
seconds. Compatibility, pack-smoke and other command-specific limits were not
changed. Generation 20 proved the timeout mismatch but was abandoned before
implementation because config-only changes were absent from implementation
fingerprints; ADR-0041 governs that independent lifecycle repair.
Generation 21 reached Implementation but was abandoned after its
config-fingerprint Green exposed a contradictory fixture baseline; it supplies
no current timeout credit.
Generation 22 was abandoned after its fingerprint Red was found to be a
malformed-journal bootstrap failure; it also supplies no current timeout credit.
Generation 23 completed the two approved cycles but retained an overbroad
nine-requirement CHANGE scope; it supplies no current timeout credit.
Generation 24 completed the narrowed-scope cycles but quality found that the
canonical execution-policy/candidate-gate design projections and two trust-test
digest constants still encoded 180000; it supplies no current release credit.
Generation 26 corrected the complete candidate-gate digest and added the
authoritative production trace identity, but quality found that the separate
no-`testRuntime` trust constant still encoded the historical 180000 projection.

## Decision

Set only the command named `test` in `.musubix/config.json` from
`timeoutMs:180000` to `timeoutMs:300000`. Select the command by its unique name,
not its array position. Preserve every other parsed config value.

Materialize the same unique value in the canonical execution-policy and
candidate-gate design projections. Bind their SHA-256 values as
`7c7ce3ed0eb363e5d43161dcd04b0dc58c3587b2cf4be9db11cca39fd521e041`
and
`414123c757dad57d01855bd408c1a3b9cf70044238df4156b2a1699bee30851f`,
respectively. These are Generation-27 historical bindings; Generation 45
supersedes both for current policy.

Generation 24 proved the config projection with
`TEST-M5-FULL-TEST-TIMEOUT-001`. Generation 25 revised that test to prove that
the live config, normative candidate-gate JSON, live candidate-gate
materialization and both trust-test constants bind the approved 300000 policy.
Its Red contained exactly the two stale trust-test digest assertions, but its
test-only fix could not change the Implementation fingerprint. Generation 26
retains that proof, changes the two constants, and adds only the approved
non-executable trace block on `candidateGateFingerprintConfig()`.

Generation 27 additionally binds the current candidate-gate projection without
the unchanged `testRuntime` member to
`2487162acfb6d862ff118819267631f8f64195358798b57bedd4cfa9602792cd`
and changes only `legacyGateSha256` in `tests/test-runtime-gate.test.ts` from
historical
`bb4a58c169b4e4f7357b608dc3b00028a613f907613b88d1540b3654ea600c8a`.
`TEST-M5-FULL-TEST-TIMEOUT-001` proves the stale-to-current transition with an
unchanged Red source through Green.

Quality uses the existing configured command evidence and requires its measured
duration to be strictly less than 300000 ms, with ordinary success and no test,
bootstrap or provenance failure. This is the Generation-27 historical quality
boundary and is superseded below for current policy. No new result schema or
validator is added.

### Generation 45 supersession

Generation 45 supersedes only the ordinary `test` timeout, its current
execution-policy digest, its current complete candidate-gate digest, and the
associated full-suite duration/headroom boundary. The configured `test`
timeout becomes exactly 900000 ms; every other command timeout, the formal
timeout, argv, and stable runtime profile remain unchanged. The standalone design-approved execution-policy projection digest becomes
`bbe82c945b29ad9fdc0656961933ba4929ba55eb13e1c61bade24f80b933941c`.
The embedded `candidateGate.executionPolicy` member changes from
`73aeed419e2feb9187153304cfbf787f124d507b28c44661193b0ac5485d19eb`
to
`a9a084af6062c318e75124631cc2080521f57bac405dff102767760d773d6993`,
and the complete candidate-gate digest becomes
`d4251d4e7be83fb03fbf551f2e8d32c0584a6d34b709a0d3fa64da3f22a00ba5`.
The approved Generation-27 legacy/no-`testRuntime` fixture digest remains
`2487162acfb6d862ff118819267631f8f64195358798b57bedd4cfa9602792cd`.
That fixture pins `test.timeoutMs` to 300000 before omitting `testRuntime`; it
is not derived by simply deleting `testRuntime` from the live Generation-45
configuration.
Quality success requires completed status, zero native/bootstrap/provenance
failures, and measured duration strictly below 900000 ms, with headroom
`900000 - durationMs`.

Fresh Generation-45 `TEST-M5-FULL-TEST-TIMEOUT-001` and
`TEST-M5-TEST-CLOCK-GATE-FINGERPRINT-001` cycles replace no historical
evidence and preserve the test source between their respective Red and Green
records.
The clock-fingerprint fixture pins the unique `test` command to 300,000
milliseconds only while constructing the legacy/no-`testRuntime` projection,
then restores 900,000 milliseconds before re-adding `testRuntime` and comparing
with the current projection. It recaptures the no-`testRuntime` approval
projection after restoring 900,000 milliseconds and uses that baseline for
current and variant comparisons. The restored no-`testRuntime` object is
persisted before that projection is recaptured. This Generation-45 repair
supersedes the non-credit Generation-44 recurrence tracked by #56.

## Consequences

Generation 27 allowed the full suite to run for up to, but not including, 300
seconds. Generation 45 supersedes that current-policy boundary with 900 seconds
for `test` only. This remains a bounded policy relaxation, not permission to
hide failures or raise other timeouts. Generations 19 through 27 remain
immutable historical evidence.

## Rejected alternatives

- Keep 180000 ms: rejected by the user's explicit policy change.
- Raise every 180000-ms command: rejected because compatibility and pack-smoke
  were not requested to change.
- Allow an open-ended or larger timeout: rejected because the approved ceiling
  was exactly 300000 ms for Generation 27 and is exactly 900000 ms for the
  Generation-45 `test` command; no open-ended ceiling is authorized.
