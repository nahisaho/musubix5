# ADR-0016: Use versioned per-file CodeGraph units with conservative fallback

## Context

The current CodeGraph always analyzes every source and stores only the assembled
graph. `graph index --changed` reports Git working-tree changes but does not use
them for safe reuse. Import, compiler, declaration, and name-resolution changes
can alter unchanged files, so optimistic per-file reuse can silently diverge
from a clean full index. Impact and cycle traversal also repeatedly filter the
complete edge collection.

## Decision

Keep `.musubix/cache/codegraph.json` as the single cache and retain
`schemaVersion: 1`, but add an `analysisVersion`, deterministic per-file
language/phase units, declaration-input fingerprints, and a resolution-
environment record. Derive `analysisVersion` from the analyzer revision and
resolved TypeScript version, and increment the analyzer revision whenever
extraction or unit semantics change. Treat a missing or mismatched version as a
full rebuild rather than attempting migration or reuse. This change assigns a
new analysis version; a pre-change cache or one missing the new metadata is an
analysis-version mismatch, not a structurally invalid current cache.

For `graph index --changed`, derive invalidation only from cached and current
fingerprints plus the resolution environment. Git changes remain
informational. Reanalyze modified ordinary sources and their transitive prior
importers; reuse all other safe units. Use deterministic full rebuilds for
cache incompatibility, resolution/configuration changes, source
additions/deletions, declaration inputs, TypeScript/JavaScript global-scope
contributors, and language declaration-map changes. Reconstruct every
cross-file declaration/module map from all current symbol-phase units before
relation extraction. The clean full index is the reference: incremental
assembly must reproduce every persisted field and array order except
`generatedAt`.

Keep run-mode, changed/analyzed/reused lists, fallback reasons, and cache-only
phase units out of the returned CLI graph. The persisted cache may carry both
the assembled semantic graph fields and cache-only metadata; callers receive a
semantic projection. Reuse the existing same-directory temporary-write and
rename mechanism so a failed replacement cannot corrupt the prior cache.

Build forward and reverse adjacency maps once for impact and cycle operations.
Preserve edge encounter order in each adjacency list, and retain the existing
stored-order architecture scan through one instrumented complete-scan helper.
Use deterministic operation counters and fixed fixtures instead of elapsed-time
thresholds. Both directions are deliberately prepared together for each graph
operation in this change so callers share one deterministic structure and the
fixed performance evidence remains simple; lazy direction-specific preparation
is a future optimization that would require a new budget.

## Rejected alternatives

- Use Git status as the incremental invalidation set: rejected because it is
  not the delta from the persisted cache and is unavailable outside Git.
- Reuse every unchanged file optimistically: rejected because additions,
  declarations, ambient scope, and configuration can change resolution without
  a prior internal import edge.
- Store analysis units in a separate graph database: rejected because it adds
  deployment, consistency, and migration complexity without a demonstrated
  need.
- Bump the public cache schema for additive analyzer metadata: rejected because
  `analysisVersion` can invalidate reuse while preserving existing schema-v1
  readers and semantic fields.
- Measure wall-clock duration: rejected because timing is environment-dependent
  and cannot provide deterministic quality evidence.

## Consequences

Common modified-source refreshes can reuse unaffected units, while ambiguous
resolution changes deliberately pay the cost of a full rebuild. Lockfile,
resolved TypeScript version, and consulted external package-manifest changes
also force a full rebuild. The cache is larger because it retains semantic
arrays and phase units, and analyzer changes must maintain the explicit
analysis version.
Tests must prove full/incremental equality, fallback precedence, atomic-write
failure behavior, Git independence, and fixed operation bounds. Traversal code
gains adjacency preparation but removes repeated edge filtering.
