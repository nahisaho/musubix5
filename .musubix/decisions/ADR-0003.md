# ADR-0003: Use append-only file journals with atomic leases

## Context

The lifecycle requires repository-wide monotonic order, crash-safe resume,
cross-process exclusion, and deterministic evidence without a native database
dependency across Node.js 20, 22, and 24.

## Decision

Use append-only canonical JSON records stored as individual order-keyed files.
Keep authoritative normal and bootstrap journals in tracked
`.musubix/journal` paths so clones and CI can verify them. Keep only shared
leases, scratch files, and a designated control-worktree locator below the
repository common Git directory. Allocate order under a global atomic directory
lease, separate from per-CHANGE leases. A fresh clone verifies the committed
chain and seeds the next order from its maximum valid order; duplicate or
divergent orders fail closed during integration. Each lease carries a fencing
token, uses a 30-second TTL, and renews every 10 seconds. Use wall-clock
deadlines only for liveness takeover; persisted order remains chronology.
Write records through create-new temporary files and platform-safe atomic
replacement, without relying on directory fsync on Windows. Verify one global
hash chain per state root and rebuild mutable compatibility JSON files as
derived projections.

## Rejected alternatives

- Wall-clock ordering: rejected because clocks can skew and move backward.
- One mutable JSON state file: rejected because partial writes and concurrent
  updates are difficult to recover safely.
- Native SQLite dependency: rejected for the initial version because it adds
  cross-platform binary packaging risk.

## Consequences

The implementation must test lock expiry, stale-holder fencing, atomic
replacement, journal verification, projection rebuilding, corruption
diagnostics, and Windows rename behavior.
