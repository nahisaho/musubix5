# ADR-0032: Emit inert CAS-safe candidate dispatch guidance

## Context

GitHub `workflow_dispatch` requires a branch or tag ref and rejects a raw commit
SHA. Strict candidate-gate attestation requires `job_workflow_sha` to equal the
candidate commit. Dispatching from an advanced default branch can therefore
produce a passing matrix whose envelopes are unusable.

Automatically creating, pushing, dispatching, or deleting a ref would cross a
repository and CI side-effect boundary. A simple `git push` or force update can
also overwrite a ref that belongs to an in-flight candidate run.

## Decision

Extend candidate-gate context with inert dispatch guidance. Derive the branch
name as
`candidate/<lowercase-change-id>-g<generation>-<first-12-candidate-commit-hex>`.
Expose that short name as `candidateBranch` and
`refs/heads/<candidateBranch>` as `candidateFullRef`. The context exposes
command descriptors as an executable plus argument array, not
shell-concatenated text.

Guidance separates inspection from mutation:

- inspect the local ref and accept only absent or exact-candidate state;
- create the local ref only when absent;
- inspect the remote ref and accept only absent or exact-candidate state;
- create the remote ref with an absent-ref lease rather than force-moving it;
- dispatch the candidate workflow with the derived ref and every fingerprinted
  input;
- after all envelopes are ingested, delete local and remote refs with
  compare-and-swap expectations bound to the candidate commit.

Human-readable CLI output and both README files explain the ordering,
collision behavior, raw-SHA limitation, the requirement that the workflow file
exist on both the default branch and candidate commit, and the in-flight
immutability rule.
The CLI emits instructions only. It performs no GitHub or ref mutation.
Strict OIDC validation remains unchanged:
`job_workflow_sha` must equal the candidate commit.

## Rejected alternatives

- Relax `job_workflow_sha` validation: rejected because it weakens proof that
  the executed workflow revision is the candidate revision.
- Dispatch from the default branch and rely only on checkout SHA: rejected
  because the OIDC workflow identity remains bound to the dispatch ref tip.
- Automatically create and delete refs: rejected because it introduces remote
  side effects and can race with in-flight runs.
- Emit shell command strings only: rejected because quoting and tokenization
  differ across shells and invite command injection or accidental splitting.
- Force-push a deterministic branch name: rejected because it can invalidate
  another run using the same ref.

## Consequences

Operators receive copyable, deterministic guidance and machine consumers
receive safe argv boundaries. Ref setup remains an explicit operator action.
Existing exact refs are reusable; collisions require a new candidate context
or cleanup rather than history rewriting.
