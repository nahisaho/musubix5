# ADR-0020: Standardize GitHub Actions on Node.js 24

## Context

The repository currently mixes Node.js 20, 22, and 24 in the candidate gate,
uses Node.js 22 on Windows and macOS, and uses Node.js 22 in release and npm
publish workflows. This provides compatibility coverage but makes the
repository's GitHub Actions runtime policy dependent on job and operating
system.

The published package declares Node.js `>=20`. The requested change concerns
the GitHub Actions execution environment and does not request removal of Node.js
20 or 22 runtime support.

## Decision

Use Node.js major version 24 for every `actions/setup-node` step in repository
GitHub Actions workflows.

Replace the five-job candidate matrix with exactly three jobs:

- Ubuntu with Node.js 24;
- Windows with Node.js 24; and
- macOS with Node.js 24.

Keep `package.json` `engines.node` at `>=20`. Treat Node.js 20 and 22 as
supported package runtimes that are no longer continuously exercised by the
candidate matrix. Do not rewrite historical candidate-gate evidence or the
pinned musubix3 baseline inventory. Persisted parsing accepts the union of the
current three Node.js 24 identities and the four retired identities
(Ubuntu/20, Ubuntu/22, Windows/22, and macOS/22), but ingestion and validation
for a new candidate accept only the current three identities. The lossless loader retains
historical records for status and deletion-invalidation reporting, while
current-set validation filters retired identities before evaluating candidate
context. New candidates must produce the new three-job Node.js 24 evidence set.

## Rejected alternatives

- Keep the existing five candidate jobs and only change Windows/macOS to
  Node.js 24: rejected because it would not unify GitHub Actions on one Node.js
  major and would retain Node.js 20/22 jobs.
- Change only the candidate gate: rejected because release and npm-publish
  workflows would continue using Node.js 22.
- Raise `engines.node` to `>=24`: rejected because the user explicitly limited
  the change to CI and retained the published Node.js `>=20` support contract.
- Add separate Node.js 20 and 22 compatibility workflows: rejected for this
  change because the requested policy is one Node.js version across GitHub
  Actions; compatibility coverage can be restored by a separately approved
  workflow if needed.

## Consequences

GitHub Actions runtime behavior becomes consistent across Ubuntu, Windows, and
macOS, and candidate approval requires three Node.js 24 records instead of five
mixed-version records.

Continuous evidence no longer demonstrates Node.js 20 or 22 compatibility even
though those versions remain supported by the package contract. Documentation
must make that distinction explicit. Historical gate records remain readable
but are excluded from current-set validation, so they cannot satisfy or block
the new current-candidate matrix.
