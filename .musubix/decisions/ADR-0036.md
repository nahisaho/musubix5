# ADR-0036: Journaled exact-hash test-source supersession

## Context

CHANGE-0017 generation 5 has current requirements approval for an additive
source-terminal maintenance operation. A valid historical Green/Refactor can
retain legitimate coverage while its authoritative test block has changed.
The SESSION motivating cycle `37836a44-2f53-44e0-b14a-c56eaa2cff50` has a
Refactor at order 3317; its fingerprint identifies the normalized canonical
test block, not the historical whole file, runner or helper environment.
Requiring unavailable historical runner commits would prevent a sound
current-snapshot comparison. Conversely, accepting a self-declared equivalent
test or a passing run alone would permit weakened assertions to rewrite TDD
history.

The existing workspace checkpoint/finalization design in ADR-0035 remains
mandatory. Its generation-4 order 3274 is immutable non-credit history and
does not become recovery authority for source maintenance. Existing migrate,
refactor, void and stale-parallel repair have distinct protected contracts.

## Decision

1. Add `tdd source-supersession prepare|approve|record|resume|replay` with the
   complete grammar in DES-M5-002 and coordinator DES-M5-023. DES-M5-011 owns
   its public ledger integration, DES-M5-007 owns pure schema/linkage checks,
   and DES-M5-004 supplies only generic journal/order/lease primitives.
   Approval/trace/runner/lifecycle/candidate evaluators are injected from the
   facade; no low-level import back into the approval or quality coordinator
   is allowed. Declared Depends-On relationships drive generated C4 output.
2. Resolve a unique current trace node and canonical test statement boundary.
   Verify supplied old block by splicing into the current file and invoking
   the existing node-aware normalized fingerprint algorithm. Preserve raw
   prefix/suffix bytes and all other inputs exactly. Pin the current declared
   dependency/production snapshot content-addressably and execute old/new
   synthetic blocks with the same runner/config/environment. Both fresh
   selected-only reports must pass. Hunk review must justify unchanged
   requirements/assertions/thresholds/failure semantics; outside-block
   changes, hidden failures and weakened tests cannot be approved away.
3. Store versioned immutable review inputs, exact-hash approvals and
   content-addressed reports/blobs at `.musubix/evidence/tdd-source/v1/`.
   This existing evidence-excluded prefix preserves Green/Refactor source,
   quality and candidate input fingerprints; prerequisite creation cannot
   satisfy the Red-to-Green implementation-change guard. They remain outside the
   unchanged requirements/design normative path set, with the exact
   schema/path boundary in DES-M5-023, not a broad specification exclusion.
   Creation cannot stale those general approvals; review/approval tampering
   remains invalid evidence. General approval cascades remain independent.
   Artifact and approval both carry top-level changeId equal to scope.changeId
   in their canonical hashes; retain DES-M5-006's closed foreign-release
   evidence selector rather than teaching it arbitrary nested ownership.
4. Separate test-only from behavior-change. Test-only adds no coverage and
   keeps the original eligible cycle once. Behavior-change links only an
   independently genuine current failed-Red/passing-Green replacement cycle,
   which supplies its own ordinary coverage once; no synthetic or relabeled
   Red, coverage transfer or provenance adoption is permitted.
5. Admit only current active-generation, requirement-owner/domain, candidate
   and current consumed-range parallel provenance bindings. Nonparallel
   null/null tuples are valid. Bind exact test/cycle/terminal kind, order,
   payload digest and old fingerprint; require different new fingerprint.
   Terminal identities, not fingerprint values, form a graph with at most one
   successor and no self/cycle/branch. Distinct identities allow A to B to A.
6. Acquire CHANGE then projection then append leases with the existing
   30-second TTL, 10-second renewal, 25ms retry and 10-second acquisition
   timeout. Validate live owner/fences at every persistence boundary.
   Durably append `tdd-source-supersession-v1` with complete admission binding
   before evidence order and ONE atomic tdd.json replacement containing both
   chain and completed projection. No chain-only crash state is supported.
   Preserve file fsync, supported directory fsync and ADR-0003 replacement.
   Migrate all tdd.json writers, including existing maintenance/repair and
   materialization paths, to locked reload/recheck/merge before enabling the
   new operation. No-active maintenance uses a repository-common named
   tdd-maintenance lease without changing its target/ownership semantics.
   Long runs hold NONE of CHANGE, maintenance, projection or append. Use
   short CHANGE -> projection -> append sections before/after execution for
   reload/recheck and required persistence, releasing every handle for the
   runner and expensive hashing. No per-test lock is required: optimistic
   target/predecessor revalidation admits only a still-current same-test
   result; unrelated tail appends merge. Prepare/approve use the same short
   publication sections and fsynced create-only publication. Install the
   shared-writer migration before enabling the source operation.
   Keep lock primitives separate from diagnostic rendering. Migrated ordinary
   candidate TDD/maintenance retains CANDIDATE_LEASE_BUSY,
   CANDIDATE_JOURNAL_BUSY and CANDIDATE_STATE_OWNERSHIP outside the approved
   lifecycle/finalization exceptions; DES-M5-023's context table fixes all
   mappings. Source-only diagnostics do not replace protected old outcomes.
7. Journal identity and request digest are replay authority. Journal envelope
   order is distinct from later evidence order. Resume reuses a unique exact
   operation order or allocates valid max+1 at that time, validates the entire
   prospective ledger and completes only its missing order/atomic-ledger
   suffix. Merge into the latest projection, retaining unrelated writers.
   Persisted admission is not recomputed from retry inputs or current source,
   but every invocation first requires its generation still be current and
   active. Exact completed replay appends nothing; divergent/corrupt/duplicate
   linkage fails closed, never deleted or waived.
8. Pending conflicts block only same repository/CHANGE/generation/test TDD
   writers or explicit target/successor mutation. Different tests, CHANGEs,
   generations and ordinary change-record checkpoints continue. Unknown
   scopes are ledger-invalid, not repository-wide pending. Existing global
   ledger and repair guards remain unchanged. DES-M5-023 fixes diagnostic
   enums, precedence, details, and exit mapping; status/gate remain read-only.
9. Add completed verified terminal (d) only to source-currency and void
   target/fallback selection. Preserve exclusive bounds, verified greatest
   order and work-scope rules. Keep migrate limited to (a)-(c), refactor
   bound to original Red, valid-Green void refusal and exact retained
   messages/exits documented in DES-M5-TDD-005. Coverage does not increase.
10. After completion, source currency compares only the new authoritative
    fingerprint with the current block fingerprint. Snapshot, dependencies,
    runner/config, production, HEAD and candidate are immutable admission
    audit bindings, not perpetual environment equality conditions. Their
    normal later changes do not stale the terminal or dedicated approval.
    Test-block drift is `TDD_TEST_STALE`; actual test failure is an independent
    normal runner/gate failure; stored approval tampering is invalid.
11. Use a TddChainRecord-compatible typed `phase:"source-supersession"` member
    with operationKey and phaseEvidenceSha256 of the canonical completed
    projection, without recursive chain-hash fields. Retain existing
    JSON.stringify chain/order hashes and byte identity; dedupe only this new
    phase by operation key, not cycleId:phase. Extend all validators/indexes/
    orphan checks together. Valid journal-only or journal+order prefixes are
    scoped pending, not orphaned phases or global invalid ledgers.
12. Existing Green/Refactor/migration selectors use the exact unique matching
    chain phaseEvidenceSha256, with migration mapped to phase migrate;
    terminal-(d) uses its defined canonical projection digest. Expose exact
    copyable selector argv in status, including before any supersession.
13. Capture a deterministic current tree from tracked plus untracked
    non-ignored paths, exact evidence/cache/journal/candidate/trace exclusions,
    materialized ignored runtime inputs, package/lock integrity and runtime/
    environment identity. stateSha256 and HEAD stability are explicit in
    DES-M5-023. Materialize independent repository-relative roots inside the
    common Git scratch area; preserve package/module/config resolution and
    reject known undeclared external inputs. Never place isolated runs inside
    the scanned source tree or resolve modules through mutable originals.
    DES-M5-023 declares dist builds, cache/report and temporary roots as
    outputs rather than immutable inputs. SESSION keeps its existing
    globalSetup local TypeScript build; each isolated run starts without dist,
    and the two post-run dist inventories must match by path/mode/raw SHA-256.
    The coordinator observes the completed runner boundary rather than an
    unspecified internal globalSetup hook. No install, fetch,
    tarball-cache availability or historical runner is prerequisite. Installed
    dependencies are copied and hash-verified against the current snapshot;
    lockfile integrity metadata is bound, not remotely revalidated.
    The guarantee is isolated roots, sanitized environment and before/after
    declared input/output manifests, not OS filesystem or network confinement.
    Environment/config cleanup prevents ambient configuration inheritance but
    does not prove absence of arbitrary external reads or network traffic.
14. Separate deterministic raw-line LCS hunks and AST preservation guards
    from semantic human attestation. Preserve assertion expressions/matchers/
    thresholds/control-flow, with only the bounded paired elapsed-clock-call
    exception for SESSION's restored recorded Refactor assertion shape
    specified in DES-M5-023. The current outside-block `vi` import, Date spy,
    try/finally and replacement expiry assertions are removed before review.
    The stronger renewal-clock assertion is out of scope because current
    production behavior already satisfies it; a first passing execution is
    never recorded as Red or given TDD credit.
    That exception still needs semantic failure review and cannot change the
    limit, units, subtraction, other assertions or clock binding/mocks.
    Prohibit new skip/only/todo/fails and changed
    block-local mock/spy behavior. Both-pass alone is never equivalence.
    Behavior-change's fresh record-time report is durably content-addressed
    before journal append, and is not a mutable retry-time dependency.
15. Readiness is scoped to evaluated active CHANGE/generation (or integration
    selected set). Other/historical valid pending remains informational.
    Abandon/reopen preserve pending without auto-completion. Historical
    source resume/replay, including completed matches, rejects exit 1
    CHANGE_GENERATION_PHASE before lease/replay lookup under unchanged
    REQ-M5-LIFECYCLE-005; no historical TDD maintenance exception is added.
    Pending prefixes remain non-credit history. Corruption
    remains non-pass. Operational I/O/launch/timeout errors retain baseline
    exit 2; domain/pending/ledger and registered lease failures use exit 1.
    DES-M5-023 traces only LIFECYCLE-006, COMPAT-013 and TDD-003 extensions;
    consumed unchanged approval/repair/lease contracts are not new coverage.
16. Pending diagnostics and sourceSupersessions summaries expose verified
     requestSha256, artifactSha256 (journal reviewSha256), approvalSha256 and
     copyable resumeArgs. Current active pending is resumable without a prior
     CLI success response; historical pending exposes hashes but no resume
     argv. Invalid hashes are null, never invented recovery authority.
17. Relevant completed P entries and source chain members participate in
     tddEvidenceSha256 and evaluated quality currency as defined in DES-M5-023.
     Omit the new digest property for scopes without P to preserve legacy
     hashes. Completion changes that digest once and invalidates an in-flight
     old-digest checkpoint, while replay is neutral. Stored checkpoints remain
     immutable admission snapshots; source completion neither creates a batch
     Green nor bypasses cascade/source/implementation guards. It clears only
     SESSION source-stale when its current block selects verified (d); renew
     affected batch, concurrency and quality evidence normally. Test-only adds
     no coverage. Historical order 3274 and inactive waivers grant none.

## Rejected alternatives

- **Mandatory historical runner/helper/dependency baseline:** rejected.
  The old test observation did not certify recoverable historical environment
  bytes, and both variants can instead be evaluated against one pinned
  current snapshot. Missing old commits/stashes alone is not disqualifying.
- **Verify old bytes by whole-file hash:** rejected. Persisted test fingerprints
  cover canonical blocks. Whole-file hashing cannot prove that historical
  whole file and unnecessarily rejects unrelated current helpers. Independent
  raw whole-file snapshot hashes remain audit bindings, never substitutes
  for node-aware old-block verification.
- **Use dependency manifest as post-completion currency:** rejected. It would
  require reapproval after ordinary implementation/helper/runner changes and
  create a permanent development loop. Manifests gate admission; test block
  fingerprints alone determine terminal source currency.
- **Reuse repair/refactor/migrate or route void implicitly:** rejected.
  Algorithm migration does not authorize real source drift; refactor preserves
  Red's fingerprint; valid Green cannot be voided; stale-parallel repair does
  not authorize arbitrary source edits. Their guards/messages/exits remain
  independent, with only the explicitly registered (d) selection extension.
- **Direct projection edit, historical rewrite or waiver:** rejected.
  These bypass immutable observations, journal/order/chain linkage and
  review. No waiver can turn pending/invalid into coverage or current source.
- **Whole-repository pending lockout:** rejected. Scoped conflict detection
  and short shared lease serialization safely permit unrelated writers.
- **Fingerprint-value graph identity:** rejected. It incorrectly forbids
  separately reviewed A to B to A while failing to model actual terminal
  identity branching and cycles.
- **Automatic current-input recomputation on resume:** rejected. It changes
  admitted intent and can lose unrelated appends. Recovery uses immutable
  journal authority and reports independent current-state failures afterward.
- **Review artifacts in `.musubix/reviews`:** rejected because that path
  participates in source/evidence-input fingerprints and could fake an
  implementation change. Reuse the existing excluded evidence boundary.
- **New incompatible hash-chain format or cycle-only dedupe:** rejected.
  Existing validators would report orphan/hash/duplicate errors and prevent
  legitimate multiple terminal identities on one cycle.
- **Persist chain and projection separately:** rejected because both live in
  tdd.json; that is neither an actual crash boundary nor safe recovery.
- **Lease only the new writer, or hold global leases during runs:** rejected.
  Unlocked old writers lose updates; long global critical sections stall
  unrelated tests. All writers migrate together with short global sections.
- **Hold the shared CHANGE lease but release only projection during runs:**
  rejected. Ordinary same-CHANGE batch checkpoints and parallel transitions
  still time out. Release all shared leases and revalidate before committing.
- **Treat rewritten dist/cache as immutable inputs, or promise unimplemented
  network/filesystem isolation:** rejected. SESSION rebuilds via globalSetup
  and creates cache-local fixtures. Declared output inventories and exact
  rebuilt-output equivalence are measurable without overstating confinement.
- **Hook or suppress Vitest globalSetup to observe mid-run dist:** rejected.
  The selected runner and config remain unchanged; each root starts without
  dist and the coordinator compares the two complete post-run inventories.
- **Approve the SESSION spy/assertion rewrite as test-only:** rejected. Restore
  the recorded assertion/control-flow and outside-block imports, supersede only
  the paired elapsed clock calls. The stronger renewal-clock assertion is
  deferred because current behavior makes an honest failing Red unavailable;
  neither deliberate production breakage nor a passing first run can create
  Red credit.
- **Resume abandoned/superseded TDD as non-credit maintenance:** rejected.
  REQ-M5-LIFECYCLE-005 does not authorize that exception; preserve the prefix
  for inspection and reject writes with CHANGE_GENERATION_PHASE.
- **Guess input closure from imports or inherit ambient module resolution:**
  rejected. Dynamic inputs and parent node_modules/config would undermine
  the frozen pair; explicit materialization and verified boundaries are
  required, otherwise fail closed.
- **Revise approved requirements solely to register these design details:**
  rejected. Approved additive-governance requirements already authorize the
  exact design registry rows. Implementation updates candidate-only
  registries/help/fixtures, preserving requirements approval and generation.
- **Exit 1 for unexpected I/O or global readiness failure for foreign pending:**
  rejected. These would change baseline operational error semantics or turn
  local unfinished work into unrelated CHANGE failure.

## Consequences

DES-M5-002 now registers exact design rows for schemas, CLI/help/success JSON,
diagnostics/exits, gate/status fields, terminal selection and input neutrality.
Implementation must update their candidate-only registries, migration guidance
and differential fixtures under the existing approved requirements before
enabling the surface. Neither requirements revision nor CHANGE bootstrap reset
is required; current design approval and the normal lifecycle still are.
This design update does not edit implementation artifacts.
Content-addressed inputs and fresh synthetic reports cost storage
and execution but make exact-hash review auditable. Unverifiable input closure
or semantic equivalence fails closed to the ordinary lifecycle.

Tests must preserve historical canonical bytes/digests across rejection,
completion, crashes and replay; cover all missing-suffix boundaries, current
max+1 after nonconflicting writes, dual replay, binding matrices, graph cycles
versus fingerprint round trips, block-only equivalence, approval manifest
independence and independent post-completion currency/failure diagnostics.
Foundation/finalization/concurrency and existing maintenance tests stay
mandatory. DES-M5-023 explicitly specifies runner-free shared-lease barriers,
SESSION build/cache equivalence, diagnostic-only resume, digest/currency,
order-3274 immutable legacy recovery and inactive-stale-waiver fixtures.
This proposed ADR does not approve design, execute TDD, create
source review evidence, or mark CHANGE-0017 complete.
