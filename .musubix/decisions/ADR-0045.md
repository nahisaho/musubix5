# ADR-0045: Use a closed Linux-only delivery profile

## Status

Proposed

## Context

CHANGE-0018 required candidate calibration, two-run candidate stability, and
release revalidation across Ubuntu, Windows, and macOS. Hosted Windows and macOS
runner behavior repeatedly blocked delivery even after deterministic scheduler,
diagnostic, lock, preparation, and LFS-verification improvements. The user chose
to retain Linux as the sole candidate and release platform while leaving
unrelated workflows and general portability code outside this change.

## Decision

Candidate calibration, candidate-gate stability, release readiness, release,
and npm publication evidence use one immutable profile:
`{profile:"linux-only-v1",os:"ubuntu",nodeMajor:24}`.

The profile is statically declared in both candidate workflows and is included
in the gate-input fingerprint, runtime context, signed envelope, calibration
manifest, stability evidence, and release verification. Verifiers fetch complete
bound-run job and artifact inventories and reject extras rather than ignoring
them. Existing three-platform evidence is not migrated and grants no credit.

Calibration uses one successful first-attempt Ubuntu observation per timing
region with the existing rounding, 3/2 margin, and caps. Stability still
requires two consecutive successful first-attempt runs, ordered by
`created_at` and numeric run ID after exhaustive pagination. Release revalidates
the calibration and both candidate runs live and fails closed when API,
artifact, OIDC, or signature evidence is unavailable.

This decision supersedes only ADR-0044's Ubuntu/Windows/macOS candidate and
release cardinality and evidence-count clauses. ADR-0044's deterministic
scheduling, bounded diagnostics, immutable evidence, timeout, LFS, signing, and
fail-closed decisions remain in force. The version-1 three-platform calibration
and stability artifacts are rejected rather than migrated; new version-2
artifacts are produced from fresh Linux-only runs.

## Rejected alternatives

### Keep the three-platform release matrix

Rejected because it contradicts the selected delivery boundary and keeps
Windows/macOS hosted-runner availability on the critical release path.

### Make the platform a workflow-dispatch input

Rejected because caller-selectable platforms would enlarge the evidence state
space, permit policy drift, and make fingerprints and release criteria
ambiguous.

### Accept only the Ubuntu envelopes from an old three-platform run

Rejected because the old run and envelope schemas bind a different matrix and
gate-input context; partial reuse would permit cross-profile replay.

### Ignore extra jobs or artifacts

Rejected because silently ignoring unexpected evidence can hide matrix drift,
workflow tampering, or ambiguous artifact ownership.

## Consequences

- Candidate and release latency and runner cost decrease.
- Windows and macOS regressions no longer block release and are not covered by
  candidate/release evidence.
- General portability tests may remain, but their hosted execution is not a
  release requirement.
- Calibration, stability, and release schemas and tests must change together.
- Every future expansion beyond Ubuntu requires a new approved delivery profile,
  requirements, design, calibration, and release evidence.

CHANGE-0019 was superseded after its generations were abandoned without release
credit. ADR-0045 becomes Accepted when the exact current CHANGE-0020 design
approval manifest is explicitly recorded.
