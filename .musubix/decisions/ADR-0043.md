# ADR-0043: Keep candidate failure diagnostics inside provenance-bound envelopes

## Context

The Generation 49 candidate passed local quality but failed the required
Ubuntu, Windows, and macOS Node.js 24 matrix twice. The existing signed
envelopes correctly preserved bounded command tails, but the Ubuntu test tail
contained only the generated report path and the macOS CLI error reported an
incomplete acknowledgment without identifying the affected command. The
existing one-envelope-per-job contract, current-run test-runtime provenance,
secret redaction, and fail-closed candidate status must remain unchanged.

## Decision

The test-runtime boundary extracts failed Vitest/Jest records only when the
matrix gate explicitly opts in and only from native report bytes already bound
by the current request, execution, acknowledgment, and result hashes. It stores
those records in a non-enumerable symbol-backed transient channel, not persisted
evidence. The gate projects them into a strict canonical JSON carrier inside raw
failed-command diagnostics only for a completed non-zero matrix command. The
candidate runner validates that carrier and performs all secret redaction,
deterministic sorting, omission accounting, and scalar bounding before the
existing result is signed and uploaded.
The gate never pre-truncates unredacted fields. It measures the exact
`JSON.stringify(candidateDiagnostics)` bytes that will be embedded in stdout
and permits at most 24,000,000 UTF-8 bytes across all structured commands. An
overflow drops the current and later command enrichment and preserves every
original failed result. The independent 100,000,000-byte runner spool cap still
governs the complete gate JSON.

Incomplete-command messages are formatted from the closed configured command
identity and runner-observed process result. Invalid acknowledgment fields are
never quoted. The exact existing incomplete-command prefix is retained so
cause classification and precedence remain stable.

## Rejected alternatives

- Upload a second raw or structured diagnostic artifact: rejected because it
  violates the exact one-envelope-per-job transport contract and creates a new
  unsigned or separately signed trust surface.
- Parse failed test output from stdout or stderr: rejected because the managed
  reporter intentionally emits only the aggregate path and console text is not
  a stable structured evidence source.
- Let the candidate runner reopen repository report paths: rejected because it
  would duplicate current-run provenance validation after the gate subprocess
  and introduce a report-replacement race.
- Persist failed-test records in `TestRuntimeProvenance`: rejected because
  diagnostics are informational and must not become evidence credit or alter
  existing candidate-gate fingerprints.

## Consequences

Failed envelopes become actionable without weakening any pass condition or
adding an artifact. The candidate result grows only within deterministic
per-entry and aggregate bounds. Malformed, unsafe, oversized, redaction-unsafe,
or unbound reports produce no enrichment and preserve the original failure.
The implementation changes content in the already-listed runtime inputs
`adapters.ts`, `gate.ts`, and `test-runtime.ts`, so the execution input digest
changes normally while the approved input path list and policy kind remain
unchanged. `candidate-gate-runner.ts` is outside that runtime-specific list.
The transient channel is excluded from `TestRuntimeProvenance`, canonical
hashes, gate fingerprints, and JSON serialization.
