# ADR-0005: Separate normative artifacts from typed evidence

## Context

Earlier designs accumulated overlapping evidence files, stale caches, and TDD
records whose first match could shadow a later valid cycle.

## Decision

Give each artifact kind its own schema and freshness contract. Bind generated
records to producer, canonical inputs, repository, candidate, CHANGE owner,
status, dependency heads, and order. Resolve requirement TDD coverage from the
latest complete Red-Implementation-Green cycle. Keep waivers non-pass.

## Rejected alternatives

- One combined evidence document: rejected because ownership and freshness
  become ambiguous.
- First matching TDD batch: rejected because stale or incomplete legacy batches
  can shadow valid successors.
- Treat unsupported or waived results as pass: rejected because it overstates
  assurance.

## Consequences

Historical records remain auditable, but only the deterministic current record
for each required kind contributes to readiness.
