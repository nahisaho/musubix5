# ADR-0031: Separate completed validation context from mutable active context

## Context

CHANGE documents use `status: active | completed`, while schema-version-1
chronology stores the current generation in `activeGeneration` and uses
`activeGeneration: null` only for abandonment. After the sole active document
becomes completed, implicit active-context resolution returns no owner.
Workflow validation then falls back to every historical declaration, and
approval and gate projections lose the generation that produced their evidence.

Changing `activeChangeContext()` to return completed CHANGEs would be unsafe.
That function protects mutable workflow, TDD, approval, candidate-gate, and
parallel operations. A global relaxation would allow new evidence to be written
against a closed CHANGE.

## Decision

Keep `activeChangeContext()` and normal `resolveChangeContext()` semantics
unchanged for mutable operations. Add a separate read-only validation resolver.

The resolver first applies the existing sole-active-document rule. If no active
document exists, it selects the completed document with the highest numeric
CHANGE identifier before inspecting chronology. That selected document is
eligible only when its current `activeGeneration` is a positive integer and its
current generation contains a quality checkpoint. Malformed identifiers,
duplicate numeric identifiers, missing chronology, null active generations,
and generations without quality fail closed. The resolver never skips an
ineligible newer completed document to report an older CHANGE as current.

An explicit maintenance selector may resolve an identified completed CHANGE
under the same eligibility rules. The selected context contains the CHANGE ID,
generation, requirement IDs, and completed document status but does not mutate
chronology or reinterpret the generation as active.

Read-only gate, status, approval validation, workflow validation, candidate
snapshot projection, and candidate-gate validation use this resolver. Workflow
reconciliation filters events by the selected CHANGE ID and generation even
when the document is completed. Approval validation threads the resolved
context explicitly into manifest comparison; the shared manifest builder
defaults to active-only resolution so approval preparation and recording cannot
inherit completed fallback. Mutation entrypoints continue to use active-only
resolution and retain their existing lifecycle diagnostics.

Completion ordering remains explicit: record the terminal `sdd-change complete`
declaration while the document is active, then set the document status to
completed. If the declaration is absent, completed validation stays scoped and
reports non-waivable `CHANGE_COMPLETION_DECLARATION_MISSING` plus recovery
guidance; it never scans all history or creates evidence automatically.

## Rejected alternatives

- Return a completed CHANGE from `activeChangeContext()`: rejected because it
  would loosen every mutable caller and permit writes against closed work.
- Validate all historical workflow declarations when no CHANGE is active:
  rejected because unrelated legacy declarations invalidate current approvals
  and encourage broad waivers.
- Add a new completed-generation field to schema-version-1 chronology:
  rejected because document status, positive current generation, and quality
  checkpoint already define the required state without repository migration.
- Select by wall-clock timestamp: rejected because timestamps are not the
  repository's authoritative monotonic ordering mechanism.

## Consequences

Completed repositories retain stable release and audit projections without
reactivating a generation. Read-only callers must explicitly choose the
validation resolver, while mutation callers remain active-only. When CHANGE
documents exist, an invalid newest completed document blocks validation and
requires explicit repair rather than exposing an older release as current.
Repositories with no CHANGE documents retain existing chronology-based
selection and fall back to all workflow history only when no chronology entry
has an active generation.
