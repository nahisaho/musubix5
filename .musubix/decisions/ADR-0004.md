# ADR-0004: Model approval review, repair, and budget as durable transactions

## Context

Repairable Reviewer findings must not immediately become approval-blocked.
Crash or resume must not double-consume attempts, repairs, nonces, or budget.

## Decision

Represent each Reviewer and repair-Planner call as a durable pending invocation
with an idempotency key. Atomically bind an accepted reservation before
consumption. Identify repair by approval boundary key and rejected output
ordinal. Cache rejected manifest findings by boundary and effective policy.
Keep verified-auto disabled by default. The design-approved orchestration
extension fixes Reviewer and repair-Planner budgets at 1000 units and the
producer repair limit at 3 for both requirements and design boundaries.

## Rejected alternatives

- Increment counters before budget reservation: rejected because denial would
  consume scarce attempts without executing a role.
- Retry identical rejected manifests: rejected because it wastes budget and can
  loop forever.
- Treat every finding as manual approval-blocked: rejected because repairable
  producer defects should return to the producer within a bounded limit.

## Consequences

The system needs explicit terminal reasons, reservation reconciliation, actual
usage records, and separate role-retry and producer-repair counters.
