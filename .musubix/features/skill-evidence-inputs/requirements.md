# Skill evidence input requirements

## REQ-M5-EVIDENCE-009: Include repository-owned Skills in evidence fingerprints
Priority: must
Type: functional
Pattern: event-driven
Statement: When non-trace implementation evidence inputs are collected for an explicitly recognized musubix source repository, the system shall include repository-owned root-relative `.github/skills/*/SKILL.md` files while continuing to exclude every repository-root `^\.github/skills/` path in repositories that are not recognized musubix sources.
Acceptance: The source-repository predicate and `isSkillSource` path definition are shared with `REQ-M5-EVIDENCE-008` and recognize only byte-exact current identity `package.json.name === "musubix5"` with object-form `package.json.repository.url === "https://github.com/nahisaho/musubix5.git"` or pinned legacy identity `musubix3` with `https://github.com/nahisaho/musubix3.git`; string repository shorthand, `git+https` variants, other names or URLs, a scalar/null/array manifest, missing or non-object repository metadata, missing manifests, unreadable manifests, and malformed JSON are non-matches that exclude Skill inputs without throwing; the existing exported synchronous `evidenceInputPaths(paths)` path-only filter retains its signature and consumer-exclusion behavior, while a new root-aware asynchronous evidence selector accepts only `root`, performs `files(root)` enumeration and one repository-manifest recognition evaluation itself, applies `evidenceInputPaths`, restores only root-relative paths matching `^\.github/skills/[^/]+/SKILL\.md$` for a recognized source repository in their original deterministic `files(root)` order, and is the sole evidence-input entry point used by TDD source fingerprints, quality-gate fingerprints, and workspace attestation; TDD keeps its test-path and configured excluded-path filtering downstream of that selector; current `.musubix/trace/index.json`, migration-era `.musubix/features/*/trace.json`, package archives, logs, and session logs are always excluded by `evidenceInputPaths` and are never restored by the root-aware selector; in a recognized repository the quality input snapshot contains each repository Skill path and content digest, and an edit to that file between the pre-run and post-run snapshots is reported as `modified`; editing, creating, deleting, or migrating either excluded trace path changes none of the TDD source fingerprint, quality input snapshot, or workspace attestation digest; a Skill-only edit also changes the TDD source fingerprint, makes persisted quality evidence with the previous fingerprint classify as `stale`, and changes the workspace attestation digest, while an edit to an excluded Skill path in an unrecognized repository or to a non-`SKILL.md` path under `.github/skills/` changes none of them; deterministic path order is preserved because persisted-quality comparison is order-sensitive; persisted quality evidence and any externally stored workspace attestation generated before the expanded input scope become stale and must be regenerated when used; in a recognized source repository, a repository Skill edit between TDD Red and Green is an eligible non-test source change and can satisfy the existing `TDD_GREEN_WITHOUT_SOURCE_CHANGE` guard, so excluding unrelated Skill edits from an open cycle remains process discipline rather than tool-enforced restart behavior; extracting and sharing the source predicate does not change `traceInputs` selection for any current, pinned-legacy, consumer, scalar/null/array, missing, unreadable, or malformed manifest fixture; user-facing workspace-attestation documentation identifies the root-aware selector and its recognized-source Skill inclusion instead of describing the path-only `evidenceInputPaths` filter as the final scope; `packages/analysis/src/tdd.ts`, `gate.ts`, and `attestation.ts` contain no direct call to `evidenceInputPaths`; `DES-M5-EVIDENCE-SKILL-001` satisfies this requirement, and trace-annotated `TEST-M5-EVIDENCE-SKILL-FINGERPRINT-001` verifies recognized current and legacy inclusion, all consumer and malformed exclusions, both trace-format exclusions and migration invariance, preserved unrelated exclusions, deterministic order, excluded non-`SKILL.md` paths, the three-module direct-call guard, the quality snapshot key/digest and in-run `modified` detection, direct persisted-quality input-currency mismatch through the helper consumed by project status's fingerprint-mismatch `stale` branch, Skill-only digest changes for TDD and workspace attestation, plus unchanged strict-trace source selection.
