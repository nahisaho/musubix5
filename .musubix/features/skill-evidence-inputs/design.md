# Skill evidence input design

## DES-M5-EVIDENCE-SKILL-001: Root-aware evidence input selector
Responsibilities: Centralize exact musubix source-repository recognition and non-trace evidence input selection so repository-owned Skill Markdown participates in TDD, quality, and workspace-attestation fingerprints without changing consumer-repository exclusions or strict-trace selection.
Interfaces: Export pure `isRecognizedMusubixSource(manifest: unknown): boolean`, shared pure `isSkillSource(path: string): boolean`, and asynchronous `evidenceInputs(root: string): Promise<string[]>` from `packages/analysis/src/files.ts`; retain exported synchronous `evidenceInputPaths(paths: string[]): string[]`; make `traceInputs(root)` call the shared predicate; make `sourceFingerprint(root, testPath, excludedPaths)`, `evidenceSnapshot(root)`, and workspace attestation call `evidenceInputs(root)`; export pure `qualityInputsCurrent(recorded: unknown, current: Record<string, string>): boolean` from `packages/analysis/src/gate.ts` for project status's fingerprint-mismatch `stale` branch and direct tests; update the workspace-attestation scope in `README.md`, while `README-ja.md` requires no change because its attestation section does not name the path filter; code node `CODE-M5-EVIDENCE-SKILL-INPUT-001` in `files.ts` implements `REQ-M5-EVIDENCE-009` and the shared predicate obligation in `REQ-M5-EVIDENCE-008`; code node `CODE-M5-EVIDENCE-SKILL-CURRENCY-001` in `gate.ts` implements `REQ-M5-EVIDENCE-009`; test node `TEST-M5-EVIDENCE-SKILL-FINGERPRINT-001`.
Constraints: `evidenceInputs(root)` calls `files(root)` exactly once, attempts to read and parse root `package.json` exactly once, treats scalar, null, array, missing, unreadable, or malformed manifests as unrecognized without throwing, and returns one filtered list in the original deterministic `files(root)` order. It first applies the unchanged root-relative path-only `evidenceInputPaths` exclusions, then restores only `isSkillSource(path)` entries matching `^\.github/skills/[^/]+/SKILL\.md$` when the shared predicate recognizes the exact current `musubix5` or pinned legacy `musubix3` manifest pair. It does not restore other root `.github/skills/` files or any trace JSON, package archive, log, or session-log path. TDD applies its target test and configured excluded-path filters only after `evidenceInputs(root)` returns; a recognized Skill edit is therefore an eligible non-test source change and can satisfy Green's source-change requirement. Quality uses the selector for both pre-run and post-run snapshots and for persisted-evidence staleness recomputation through `qualityInputsCurrent`; absent, null, array, non-object, non-string-valued, or mismatched recorded fingerprints return false without throwing, exact ordered equality returns true, and aggregate-check, performance, mutation, correspondence, approval, and other stale conditions remain outside this helper and behaviorally unchanged. Workspace attestation uses the same selector. `traceInputs(root)` preserves its existing artifact and programming-language selection, uses the shared predicate only for Skill inclusion, and remains non-throwing for manifest failures. The shared predicate's code annotation implements both `REQ-M5-EVIDENCE-009` and `REQ-M5-EVIDENCE-008`, while the machine-readable design satisfaction edge for `REQ-M5-EVIDENCE-008` remains owned by `DES-M5-TRACE-SKILL-001`; relocating that implementation detail does not add REQ-M5-EVIDENCE-008 to CHANGE-0011's normative scope. `TEST-M5-EVIDENCE-SKILL-FINGERPRINT-001` behaviorally proves that the three consumers observe recognized Skill changes, directly covers valid, missing, malformed, and mismatched currency inputs, and uses source-text inspection to assert that `packages/analysis/src/tdd.ts`, `gate.ts`, and `attestation.ts` contain no call to `evidenceInputPaths`. The selector adds no cache spanning evidence collections, because each collection must observe its own current repository identity and file set; an identity change during a quality run may therefore surface unchanged Skill files as added or deleted input-stability entries. Existing persisted quality evidence and any externally stored workspace attestation are expected to become stale after this scope change and are regenerated when used rather than migrated. The `README.md` target-behavior edit is finalized before the implementing Red baseline and remains unchanged through Green. Unrelated Skill or documentation edits are kept out of an open TDD cycle by process discipline because the TDD engine intentionally accepts any eligible non-test source change.
