# CodeGraph Performance Design

## Scope

This design accelerates the existing in-process CodeGraph implementation while
preserving the clean full index as the semantic reference. It adds no external
database, no new source language, and no new call-resolution semantics.

## DES-M5-GRAPH-001: Incremental index planner and report
Responsibilities: Classify the prior cache, compare current invalidation and resolution-environment fingerprints with cached metadata, run non-contributing declaration probes, choose incremental reuse or one deterministic full-rebuild reason, compute the prior-graph transitive importer closure for safe modified-source reuse, and produce the CLI indexing report independently from the persisted semantic graph.
Interfaces: `graphInputs(root)`; new `declarationInputs(root)` and `resolutionEnvironment(root, priorManifestPaths)` that re-fingerprints the prior logical consulted-manifest set plus current lockfiles and TypeScript version; resolution-manifest reader that follows package-manager symlinks read-only, never uses `snapshot`/`safePath`, and returns hash or `absent` instead of throwing; syntax/declaration probe `probeGraphDeclarations(root, changedSources, program)` that emits no graph contribution and increments no operation counter; cached semantic and invalidation fingerprints; `indexGraph(root, { persist, refresh, runner, writer })` returning `CodeGraphIndexResult` with `graph`, `indexing`, and operation counters; planner-owned informational Git wrapper using the injected `Runner` to map missing/error/nonzero results to `changed: null` while leaving shared `changedFiles` throwing behavior unchanged; CLI `graph index [--changed]`; full-persisting `graph gate`; non-persisting callers in `packages/analysis/src/change.ts` and matrix gate execution; fallback reasons `FULL_REQUESTED`, `CACHE_MISSING`, `CACHE_INVALID`, `ANALYSIS_VERSION_MISMATCH`, `CONFIG_CHANGED`, `DECLARATION_CHANGED`, `DELETED_FILES`, and `ADDED_FILES`.
Constraints: Fingerprint comparison, not Git status, is the sole invalidation authority; external manifest absence, unreadability, or refused resolution is represented as `absent` and selects `CONFIG_CHANGED` on difference; Git lookup failure yields `changed: null` and does not fail indexing; reason selection follows the requirement-defined precedence after declaration probing; probes cannot mutate graph state or increment analyzed/reused counters; fallback discards probe state before extraction counters start; a no-change refresh returns the cached graph without rewriting it; added, deleted, renamed, resolution-environment, configuration, declaration-input, cross-file declaration-map, script-mode, and `declare global` changes take the conservative full path; changed ordinary sources reanalyze the source and prior internal-importer closure; `persist: false` always produces a deterministic clean in-memory full graph without reading or writing reusable cache metadata; changed inputs use root-relative/logical paths and reserved token `@resolution/typescript` for a version-only change; every reported string list is sorted; run-mode/report fields never enter `codegraph.json`.
Requirements: REQ-M5-GRAPH-001
ADRs: ADR-0016

## DES-M5-GRAPH-002: Versioned analysis units and deterministic cache assembler
Responsibilities: Extract cacheable per-source, per-language-phase CodeGraph units, reconstruct every cross-file declaration/module map from cached and analyzed symbol-phase units before relation extraction, construct one complete current TypeScript program for typed-source extraction, recompute graph-level outputs, combine analyzed and reused contributions in the exact clean-full language/phase sequence, and atomically persist one analyzer-versioned cache.
Interfaces: internal `CodeGraphCache` extending the semantic `CodeGraph` fields with `analysisVersion`, declaration and resolution-environment fingerprints, and cache-only phase units stripped from CLI and `loadGraph` results; per-path `symbolsPhase` and `relationsPhase` contribution buckets for imports, symbols, calls, diagnostics, and consulted logical external manifests; graph-level recomputation for `unsupportedFiles`, `entrypoints`, `GRAPH_UNSUPPORTED_LANGUAGE`, `GRAPH_MANIFEST`, and the program-creation `GRAPH_TSCONFIG`; per-source TypeScript config-diagnostic attribution keyed to the first consuming typed source in current typed-source order; cross-file maps `javaTypes`, `csharpTypes`, `phpTypes`, `juliaModules`, `kotlinDeclarations`, Scala declarations, Elixir modules, Haskell modules, F# declarations, Visual Basic declarations, Go module metadata, and Dart package metadata; language-specific indexers in `packages/analysis/src/graph.ts`; TypeScript `Program` and `TypeChecker`; fresh `snapshot(root, graphInputs(root))` preserving traversal key order; semantic projection helper used by both index results and `loadGraph`; injectable cache writer defaulting to existing `writeJson`; configured `codegraph-tests` command backed by `scripts/run-codegraph-tests.mjs`, using Vitest JSON task results for exact one-test identity and writing targeted plus aggregate `musubix-json` reports under `.musubix/cache/test-results`; diagnostic `CACHE_WRITE_FAILED`; authoritative tests `TEST-M5-GRAPH-INCREMENTAL-001`, `TEST-M5-GRAPH-INCREMENTAL-NOCHANGE-001`, `TEST-M5-GRAPH-INCREMENTAL-FALLBACK-001`, `TEST-M5-GRAPH-INCREMENTAL-GIT-001`, and `TEST-M5-GRAPH-CACHE-WRITE-001`.
Constraints: `analysisVersion` combines the musubix analyzer revision and resolved TypeScript package version and changes whenever extraction or unit semantics change; missing or mismatched analyzer versions are never reused; phase units contain no timestamps and the assembler mirrors the existing typed-first then language-major symbols/relations sequence exactly; the emitted consulted-manifest set is the sorted union of all current units, so removed imports remove stale manifests; graph-level outputs are recomputed on every emitted graph rather than reused as source units; the config resolved by the program-creation `optionsFor('index.ts')` call is recomputed as graph-level state, its `GRAPH_TSCONFIG` diagnostics are emitted after `GRAPH_UNSUPPORTED_LANGUAGE` and before `GRAPH_MANIFEST` even when no typed source consumes that config, and its memoization key seeds per-source extraction so it is not emitted twice; only configs first loaded by per-source extraction are attributed to the first consuming typed source in current typed-source order; the fallback/equality fixture includes an invalid root config plus a nested-config source to prove exact ordering; every cross-file map is rebuilt bit-identically from all current symbol-phase units before any affected relations phase executes, otherwise a modification in that language selects `DECLARATION_CHANGED`; cache-only metadata is stripped before returning CLI fields and by `loadGraph`, whose semantic stale-cache validation remains based on the existing semantic fingerprints; declaration and resolution fingerprints do not alter semantic `files`, `unsupportedFiles`, or `fingerprints`; typed-source extraction may reuse units only after the full current program has been created with unchanged compiler options; semantic `fingerprints` always come from one fresh snapshot in `graphInputs` traversal order; operation counters increment only for extraction contributing to the emitted graph; the runner treats zero or multiple exact task matches, skipped tasks, and process/result disagreement as non-pass, its hardcoded nine-ID list is normative and must remain identical to the authoritative test annotations, operation sidecar writes are optional and no-op when the environment variable is absent under the ordinary parallel Vitest command, and the aggregate command timeout is 300 seconds; failed temporary write or rename removes the temporary file, preserves the previous cache byte-for-byte, and surfaces `CACHE_WRITE_FAILED`; the injectable writer provides a deterministic failure seam without permission-dependent tests.
Requirements: REQ-M5-GRAPH-001
ADRs: ADR-0016
Depends-On: DES-M5-GRAPH-001

## DES-M5-GRAPH-003: Indexed graph traversal and operation instrumentation
Responsibilities: Build forward and reverse adjacency maps once for impact, change-fingerprint dependency expansion, and cycle operations, preserve stored import ordering in neighbor lists, run Tarjan traversal from the prepared forward map, and route deliberate complete post-preparation import scans through one measurable primitive.
Interfaces: internal `GraphAdjacency` with forward and reverse maps; explicit optional `GraphOperationCounters` sink passed per invocation rather than module-global state; `graphImpact`; `cycles`; `graphGate`; dependency expansion in `packages/analysis/src/change.ts`; rule-major architecture scan primitive; authoritative tests `TEST-M5-GRAPH-TRAVERSAL-001`, `TEST-M5-GRAPH-CYCLES-001`, `TEST-M5-GRAPH-GATE-SCAN-001`, and `TEST-M5-GRAPH-GATE-ORDER-001`; performance budget `forwardAdjacencyVisits <= 13` for the six-file, seven-internal-edge fixture.
Constraints: Each adjacency direction initializes one bucket per file and inserts each internal edge once; external edges never enter adjacency maps; impact breadth-first discovery and `via` selection retain prior import encounter order; cycle component and result sorting remain unchanged; `change.ts` uses prepared forward neighbors instead of repeated `graph.imports.filter`; architecture evaluation preserves rule-major outer iteration and stored edge order, and `completeImportScans` increments once per rule; counters are caller-owned and reset by creating a new sink per test entry; the one-rule positive control reports one scan, while the separate two-rule ordering test verifies rule-major diagnostic order.
Requirements: REQ-M5-GRAPH-002
ADRs: ADR-0016
Depends-On: DES-M5-GRAPH-001

## Verification and handoff

Implementation proceeds in two requirement batches:

1. `REQ-M5-GRAPH-001`: write the incremental-index test and structured report,
   record Red, implement the planner/analysis-unit/cache path, record Green, and
   run the separate no-change, fallback, Git-unavailable, and atomic-write
   regressions.
2. `REQ-M5-GRAPH-002`: write the traversal operation-count test and report,
   record Red, introduce adjacency indexes and the scan primitive, record Green,
   then run cycle and architecture positive-control regressions.

After both batches, run full typecheck, build, tests, strict trace, graph gate,
changed quality gate, and status. Cache-format and output compatibility are
reviewed against both plain full indexing and changed refresh.
