# CodeGraph Performance Requirements

## Scope

These requirements improve the existing CodeGraph implementation without
changing the semantic results of a clean full index or the established
`graph index`, `graph impact`, `graph cycles`, and `graph gate` contracts.

## REQ-M5-GRAPH-001: Refresh a valid CodeGraph cache incrementally
Priority: must
Type: functional
Pattern: event-driven
Statement: When `graph index --changed` is invoked with a valid prior CodeGraph cache, the system shall reuse unchanged analysis safely and refresh the graph from the smallest conservatively valid source set.
Acceptance: A cache is reusable only when it parses, satisfies the CodeGraph schema, records the current `analysisVersion`, and contains valid per-file analysis for its recorded input fingerprints; this change assigns a new `analysisVersion`, and a pre-change cache or any cache missing declaration or resolution-environment metadata is classified as `ANALYSIS_VERSION_MISMATCH`, not `CACHE_INVALID`; for `graph index --changed` only, differences between cached and current invalidation fingerprints form the invalidation set and are not classified as cache staleness, while `graph impact`, `graph cycles`, and `graph gate` retain existing stale-cache rejection; invalidation fingerprints are derived solely from a fresh snapshot of `graphInputs(root)`, a separate `declarationInputs(root)` set matching repository files with `.d.ts`, `.d.cts`, or `.d.mts` suffixes, and a resolution-environment record containing the resolved TypeScript version, fingerprints of present `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, and `yarn.lock`, and refreshed states for the logical external package-manifest paths recorded by prior per-source phase units; an external manifest state is its content hash or a distinguished `absent` value, a manifest that does not exist yields `absent` and is compared like any other state, and only unreadable or refused reads select `CONFIG_CHANGED` rather than throwing; each source phase unit records the logical external manifests it consulted, and the emitted manifest set is the sorted union over all current reused and analyzed units so removed consultations disappear; declaration and resolution-environment fingerprints are stored only in versioned cache metadata and do not alter the existing semantic `fingerprints`, `files`, or `unsupportedFiles` fields; the existing top-level JSON `changed` field remains the informational Git working-tree list and never widens or narrows reuse; when Git metadata is unavailable, `graph index --changed` completes with exit code 0, reports `changed: null`, emits no graph diagnostic for that informational absence, and leaves fingerprint invalidation plus every `indexing` field unaffected; modifying an existing non-declaration source reanalyzes that source plus the transitive closure of its importers from the prior internal import graph, with TypeScript analysis using a program containing the complete current typed-source set and unchanged compiler options; any added, deleted, or renamed source triggers `ADDED_FILES` or `DELETED_FILES`; any changed declaration input, any modified TypeScript or JavaScript source that the resolved compiler program treats as a script rather than an external module or that contains a `declare global` augmentation, and any modification that changes cached declaration-map names used by a name-resolved language indexer triggers `DECLARATION_CHANGED`; any changed `tsconfig*.json`, `package.json`, `go.mod`, `pubspec.yaml`, resolution lockfile, resolved TypeScript version, or previously consulted external package manifest triggers `CONFIG_CHANGED`; each of those triggers causes a full rebuild, and proven-equivalent incremental handling for those categories is outside this change; an absent cache uses `CACHE_MISSING`, an unparsable or structurally invalid current-version cache uses `CACHE_INVALID`, and a missing or non-matching `analysisVersion` uses `ANALYSIS_VERSION_MISMATCH`; when multiple reasons apply, the single reported reason is selected by this precedence: `CACHE_MISSING`, `CACHE_INVALID`, `ANALYSIS_VERSION_MISMATCH`, `CONFIG_CHANGED`, `DECLARATION_CHANGED`, `DELETED_FILES`, then `ADDED_FILES`, with a rename represented by deleted and added paths and therefore selecting `DELETED_FILES` unless a higher reason applies; the refreshed persisted graph and its cache metadata are deterministic and identical to a clean full index after excluding only `generatedAt`, including exact array order for files, unsupported files, imports, entrypoints, symbols, calls, diagnostics, fingerprints, `analysisVersion`, declaration-input fingerprints, resolution-environment metadata, and canonically path-ordered per-file phase units that contain no timestamps; the cache keeps `schemaVersion: 1`, contains no run-mode fields, and is written to a uniquely named temporary file in `.musubix/cache` before same-directory rename over `codegraph.json`, with failed temporary files removed; if the temporary write or rename fails, the command exits nonzero with diagnostic `CACHE_WRITE_FAILED` and leaves any pre-existing `codegraph.json` byte-identical and reusable, so interruption cannot expose a partially written reusable cache; CLI JSON retains the top-level graph fields and `changed` field, excludes cache-only metadata and units, and adds exactly `indexing: { mode, changedInputs, analyzedSourcePaths, reusedSourcePaths, fullRebuildReason? }`, where `mode` is `incremental` or `full`, each string array is sorted, `changedInputs` includes root-relative changed source, declaration, configuration, lockfile, and logical manifest paths plus reserved token `@resolution/typescript` when only the resolved TypeScript version changed, `analyzedSourcePaths` and `reusedSourcePaths` partition exactly the current semantic `graph.files` source set and exclude declaration/configuration-only inputs, and `fullRebuildReason` is present only in full mode; `graph index` without `--changed` reports full mode, `fullRebuildReason: FULL_REQUESTED`, empty `changedInputs`, all current `graph.files` entries in `analyzedSourcePaths`, and an empty reused list; the text summary ends with `(incremental)` or `(full: <reason>)`; a reusable cache with no fingerprint changes reports incremental mode with empty changed/analyzed arrays, all current `graph.files` entries reused, `operations.analyzedSourceFiles = 0`, `operations.reusedSourceFiles = graph.files.length`, does not rewrite the cache, and preserves `generatedAt`; `operations.analyzedSourceFiles` increments once when one semantic graph source's contributing extraction units execute and excludes declaration probes plus creation, parsing, and binding of the complete TypeScript program, `operations.reusedSourceFiles` increments once when one current semantic graph source's cached phase units are copied without executing contributing extraction, discarded probe or fallback work increments neither counter, and those counters equal the lengths of `analyzedSourcePaths` and `reusedSourcePaths`; `TEST-M5-GRAPH-INCREMENTAL-001` is the sole counter-reporting test for the six-source modified-leaf scenario, emits exactly one `musubix-json` entry with `operations.analyzedSourceFiles = 2` and `operations.reusedSourceFiles = 4`, and asserts equality between the incremental and clean-full persisted graphs after excluding only `generatedAt`; separate non-counter regression tests `TEST-M5-GRAPH-INCREMENTAL-NOCHANGE-001`, `TEST-M5-GRAPH-INCREMENTAL-FALLBACK-001`, `TEST-M5-GRAPH-INCREMENTAL-GIT-001`, and `TEST-M5-GRAPH-CACHE-WRITE-001` verify respectively the no-change path, declaration/configuration/resolution-environment/full-rebuild reasons plus precedence and plain full-index reporting, Git-unavailable behavior, and atomic-write failure behavior without emitting duplicate `TEST-M5-GRAPH-INCREMENTAL-001` report entries.

## REQ-M5-GRAPH-002: Traverse CodeGraph edges with linear preparation
Priority: must
Type: non-functional
Pattern: ubiquitous
Statement: The system shall prepare forward and reverse CodeGraph adjacency indexes once per graph operation and use them for impact analysis and cycle detection.
Acceptance: `graph impact`, `graph cycles`, and the cycle portion of `graph gate` preserve their existing deterministic results and diagnostics for identical graph inputs; forward and reverse adjacency construction visits each file and internal import edge at most once per constructed direction, subsequent neighbor lookup performs no complete import-edge rescan, reverse adjacency lists preserve stored import order so `graphImpact` paths and `via` chains remain unchanged, and architecture-rule evaluation continues to scan `graph.imports` in stored order so `GRAPH_ARCHITECTURE` diagnostic order remains unchanged; `operations.forwardAdjacencyVisits` and `operations.reverseAdjacencyVisits` each increment once for initialization of one file bucket and once for insertion of one internal import edge into the respective index, while every complete post-preparation pass over `graph.imports` is routed through one instrumented scan primitive that increments `operations.completeImportScans`, including architecture-rule evaluation but excluding adjacency construction; `TEST-M5-GRAPH-TRAVERSAL-001` is the sole performance-reporting traversal test, uses a branching acyclic fixture with exactly six files and seven internal import edges, resets counters before the operation, emits exactly one `musubix-json` entry with `operations.forwardAdjacencyVisits = 13`, `operations.reverseAdjacencyVisits = 13`, and `operations.completeImportScans = 0`, and asserts exact symbol/path impact results and `via` chains; the machine-enforced performance budget applies to `forwardAdjacencyVisits`, while reverse-visit and complete-scan values are exact in-test assertions; separate regression test `TEST-M5-GRAPH-CYCLES-001` covers self-cycles, multi-file strongly connected components, and external-edge exclusion without emitting a duplicate traversal performance entry; separate positive-control test `TEST-M5-GRAPH-GATE-SCAN-001` resets counters, evaluates one architecture rule, and proves `operations.completeImportScans = 1` plus unchanged architecture diagnostics and ordering.
