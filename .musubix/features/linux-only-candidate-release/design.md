# Linux-only candidate and release design

## DES-M5-LINUX-DELIVERY-001: Immutable Linux delivery profile
Responsibilities: Define one closed delivery profile for candidate calibration, candidate verification, signed envelopes, and release evidence; remove the operating-system matrix from the two candidate workflows without making the platform caller-selectable.
Interfaces: `.github/workflows/candidate-calibration.yml`; `.github/workflows/candidate-gate.yml`; shared `LINUX_DELIVERY_PROFILE`, `validateLinuxDeliveryProfile()`, and `validateSingleUbuntuRunInventory()` in `packages/analysis/src/candidate-delivery-profile.ts`; candidate workflow context and envelope schemas in `packages/analysis/src/candidate-gate.ts` and `packages/analysis/src/candidate-gate-runner.ts`; gate-input projection in `packages/analysis/src/config.ts`; workflow contract tests in `tests/candidate-gate-workflow.test.ts`, `tests/candidate-calibration-workflow.test.ts`, and `TEST-M5-LINUX-CANDIDATE-WORKFLOW-001`.
Constraints: The profile constant is exactly `{profile:"linux-only-v1",os:"ubuntu",nodeMajor:24}` and is included in the gate-input fingerprint, runtime dispatch, result, OIDC audience/context validation, artifact identity, calibration manifest, and stability evidence. Candidate result/envelope, calibration, and stability schemas advance to version 2 and require the profile field; a version-1, missing-profile, or foreign-profile value is normalized to `LINUX_DELIVERY_EVIDENCE_INVALID` rather than leaking parser-specific errors. Both workflows contain one statically declared Ubuntu job and no matrix strategy or platform input. The shared inventory validator receives a closed workflow kind plus the expected job and artifact identities and the complete jobs and artifacts returned for one bound workflow run; it requires every item to bind the same workflow run ID and accepts exactly the expected Ubuntu job and artifact for either calibration or candidate-gate execution. Calibration ingestion, stability verification, and release verification all call it and reject duplicates, extras, or foreign ownership with `LINUX_DELIVERY_EVIDENCE_INVALID`. Old CHANGE-0018 and three-platform envelopes lack the profile binding and cannot be adapted, upgraded, or replayed. The seven-command execution plan, retry prohibition, timing limits, signing boundary, LFS closure, immutable candidate, and failure-envelope behavior remain unchanged.

ADRs: ADR-0045
Depends-On: DES-M5-CI-EFFICIENCY-001 DES-M5-CI-EFFICIENCY-004

## DES-M5-LINUX-DELIVERY-002: Single-observation calibration ingestion
Responsibilities: Ingest one successful no-credit Ubuntu calibration envelope, calculate Linux candidate deadlines, and persist a calibration manifest that cannot be confused with the prior three-platform schema.
Interfaces: `.musubix/candidate-timeout-calibration.json`; `packages/analysis/src/candidate-calibration.ts`; calibration types and timeout calculation in `packages/analysis/src/candidate-execution-plan.ts`; GitHub run/job/artifact and OIDC verification in `packages/analysis/src/candidate-gate.ts`; `TEST-M5-LINUX-CALIBRATION-001`.
Constraints: The version-2 calibration schema stores `deliveryProfile:"linux-only-v1"`, one run identity, one first-attempt projection, one Ubuntu job identity, one artifact identity, one envelope/OIDC digest pair, one Jobs API timing projection digest, one runtime LFS-manifest digest, and one logical closure digest. Ingestion obtains exhaustive jobs and artifacts for the bound run and maps duplicates, extras, missing values, unavailable API pages, reruns, non-success, censorship, nonzero commands, timeout, or context mismatch to `LINUX_DELIVERY_EVIDENCE_INVALID`. It recomputes the gate-input fingerprint from the current approved repository, candidate, CHANGE generation, plan, calibration, LFS closure, and `linux-only-v1` profile through `packages/analysis/src/candidate-gate.ts`; an envelope-provided fingerprint is comparison input only and cannot define the expected context. Bootstrap, preparation, signing, and upload observations come from the bound Jobs API step-timing projection; preconditions, each command partition/wave, report merge, bounded termination, each closed command, formal execution, post-conditions, and persistence come from the signed envelope's canonical completed-region timing map. Every calibrated region uses the existing region names and caps from `REQ-M5-CI-EFFICIENCY-003`; integer millisecond arithmetic computes `ceil(observation / 1000) * 1000 * 3 / 2`, where an exact multiple remains unchanged, and compares the multiplied result to its cap before persistence, rejecting instead of clamping. Source/final direct-parent and limited-tree-diff rules remain unchanged. The loader accepts only version 2; the previous three-platform calibration file is regenerated from a new Linux-only source run, is rejected on load, is never migrated, and grants no credit.

ADRs: ADR-0045
Depends-On: DES-M5-LINUX-DELIVERY-001 DES-M5-CI-EFFICIENCY-001 DES-M5-CI-EFFICIENCY-004

## DES-M5-LINUX-DELIVERY-003: Linux first-attempt stability verifier
Responsibilities: Select and live-revalidate two consecutive successful first-attempt Linux candidate runs while preventing tied timestamps, pagination gaps, reruns, or historical cross-profile evidence from creating false adjacency.
Interfaces: `packages/analysis/src/candidate-stability.ts`; version-2 stability evidence persisted by the candidate status integration; `validateSingleUbuntuRunInventory()` and deterministic run comparator in `packages/analysis/src/candidate-delivery-profile.ts`; GitHub client projections in `packages/analysis/src/candidate-gate.ts`; `TEST-M5-LINUX-STABILITY-001`.
Constraints: The canonical workflow identity is derived from repository identity plus the pinned path `.github/workflows/candidate-gate.yml`; each API lookup resolves that path to the same workflow ID and no caller-supplied numeric ID is accepted. The verifier exhaustively paginates Runs API results matching that resolved identity, `workflow_dispatch`, and immutable candidate head SHA. It sorts them by `created_at` ascending and numeric run ID ascending, requires two distinct run IDs, and deterministically selects the newest qualifying adjacent pair whose current and first-attempt endpoints both conclude `success` with `run_attempt === 1`; failed, cancelled, queued, or older runs outside the selected pair do not invalidate it, while every other matching total-order key strictly between the selected runs is intervening regardless of conclusion or lifecycle state. It fetches the complete job and artifact inventories for both runs and calls the shared validator to accept exactly one Ubuntu Node.js 24 job and artifact per run. Both `linux-only-v1` envelopes must share repository, candidate, CHANGE, generation, plan, calibration, timeout-excluded input, logical LFS closure, and final gate-input bindings while retaining distinct run/job/nonce-bound LFS manifests. Missing pages, API errors, extra identities, expired artifacts, invalid OIDC, mismatched bindings, or job-to-artifact duration above 1,200,000 milliseconds map to `LINUX_DELIVERY_EVIDENCE_INVALID`. The stability loader accepts only version 2; version-1 three-platform stability evidence is never migrated and grants no credit. Only the later run supplies the authoritative gate set and the earlier run remains bound stability evidence.

ADRs: ADR-0045

## DES-M5-LINUX-DELIVERY-004: Linux-only release evidence guard
Responsibilities: Revalidate the approved Linux calibration and both Linux stability runs at release-readiness, release, and publication boundaries; prevent cached, stale, cross-profile, or extra-platform evidence from granting release credit.
Interfaces: release readiness in `packages/analysis/src/candidate-gate.ts`; stability integration in `packages/analysis/src/candidate-stability.ts`; `packages/analysis/src/release-manifest.ts`; `packages/analysis/src/release-operation-guard.ts`; `.github/workflows/release.yml`; `.github/workflows/npm-publish.yml`; `TEST-M5-LINUX-RELEASE-001`.
Constraints: Each release evaluation re-fetches the calibration run, both candidate runs, every first/current attempt, complete job/artifact inventories, artifact creation times, OIDC claims, and signed envelopes; calls the shared inventory validator for all three bound runs; repeats the deterministic total-order adjacency query; retains the earlier run as stability evidence; and validates the current approved candidate, generation, delivery profile, plan, calibration, LFS, timeout, quality, and approval bindings. Invalid, malformed, stale, cross-profile, extra, mismatched, unavailable, incomplete, expired, API-failed, artifact-fetch-failed, OIDC-failed, or signature-failed evidence maps to `LINUX_DELIVERY_EVIDENCE_INVALID`; no condition permits cached success or success-shaped fallback. An artifact is stale when its candidate commit, generation, delivery profile, or gate-input fingerprint differs from the current approved context. The guard requires no Windows or macOS evidence but rejects any extra job or artifact in a bound calibration or candidate run. The guard emits a signed or content-digest-bound verified Linux release context containing both stability run identities and the authoritative later envelope; `.github/workflows/release.yml` and `.github/workflows/npm-publish.yml` accept only that exact guard output and revalidate its digest against the approved release manifest before publication. Release and npm publication do not change package contents, provenance, or human release-approval requirements.
