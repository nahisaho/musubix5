## DES-M5-CI-002: Bounded Unix-socket test fixture
Responsibilities: Provide a POSIX-only callback fixture that binds the parallel-runtime overlay-copy failure socket through a short unique alias while placing the real socket entry inside the fixture repository, and remove the temporary candidate-workflow environment workaround once the fixture is self-contained.
Interfaces: `createShortSocketDirectory(base = '/tmp')` and `withShortUnixSocket(targetDirectory, callback, base = '/tmp')` in `tests/fixtures/short-unix-socket.ts`; `ShortUnixSocketContext` containing `socketPath`, `targetSocketPath`, and `shortDirectory`; `TEST-M5-CI-SHORT-SOCKET-PATH-001` in `tests/short-unix-socket.test.ts`; `TEST-M5-CI-DEFAULT-TMPDIR-001` and `TEST-M5-CI-NODE24-001` in `tests/candidate-gate.test.ts`; `TEST-M5-PARALLEL-WORKSPACE-PARTIAL-COPY-001` in `tests/parallel-release-blockers-generation5.test.ts`; the `Run closed verification matrix` step in `.github/workflows/candidate-gate.yml`.
Constraints: `createShortSocketDirectory()` calls `mkdtempSync(join(base, 'm5s-'))`, returns a newly created mode-0700 directory, and wraps creation failure in an error that names `base`; normal callers omit the `base` test seam. `withShortUnixSocket()` rejects Windows before mutation, computes `<shortDirectory>/target/z-overlay-copy-failure.sock`, and rejects a UTF-8 pathname longer than 90 bytes before creating the directory symlink or calling `listen()`, removing the unique directory before propagating the length error. For a bounded path it creates the `target` directory symlink pointing to the caller's existing target directory and binds through that symlink; `targetSocketPath` is exactly `join(targetDirectory, 'z-overlay-copy-failure.sock')`. It creates and owns the `node:net` server, attaches both `listening` and `error` handling before `listen()`, rejects bind errors with the path and byte length, invokes the async callback exactly once only after listening, and in `finally` closes only a started server, waits for `close` when applicable, tolerates the socket entry already being absent after close, removes a remaining entry through `targetSocketPath` only when this server reached `listening` and the entry is a socket, then recursively removes only its exact unique short directory without traversing the `target` directory symlink. Cleanup covers callback success, callback failure, bind failure, and overlength rejection; it is idempotent and preserves and rethrows the callback, bind, or length error unless cleanup itself is the only failure. A pre-existing non-socket target entry survives bind failure. The module imports neither `node:os` nor application code and reads no temporary-directory environment variables. The `CODE-M5-CI-SHORT-SOCKET-001` annotation contains `@implements REQ-M5-CI-002` and `@design DES-M5-CI-002` but no `@verifies`; the existing candidate-workflow `CODE-M5-CI-NODE24-001` annotation adds `REQ-M5-CI-002`; test annotations remain separate so strict trace classifies implementation and test evidence independently. `TEST-M5-CI-SHORT-SOCKET-PATH-001` runs platform-independent source checks everywhere; on Windows it asserts early rejection, while on POSIX it uses two helper invocations to prove uniqueness, verifies mode and byte bound, derives and later removes a controlled base with one padding component whose length is `max(1, 91 - Buffer.byteLength(join(resolvedParent, 'm5s-XXXXXX', 'target', 'z-overlay-copy-failure.sock'), 'utf8'))`, keeps that component at most 255 bytes, asserts the resulting candidate is longer than 90 bytes, then proves reachable length rejection and unique-directory cleanup; it observes the real target socket entry while listening, provokes a handled bind error with a pre-existing non-socket entry and proves that entry survives, forces a callback failure and proves that the same error is rethrown after cleanup, confirms a sentinel and target directory survive, and invokes `createShortSocketDirectory()` with a missing-parent base to verify the diagnostic. `TEST-M5-CI-NODE24-001` stops requiring the positive `TMPDIR` expectation while retaining its Node.js, matrix, artifact, documentation, and compatibility assertions. `TEST-M5-CI-DEFAULT-TMPDIR-001` verifies `REQ-M5-CI-002` and asserts across the whole workflow document that no `env` mapping assigns `TMPDIR` and no command writes `TMPDIR` to `GITHUB_ENV`; this prohibition is workflow-scoped and does not forbid a focused subprocess test from setting `TMPDIR` to construct a deliberate cross-filesystem fixture. `TEST-M5-PARALLEL-WORKSPACE-PARTIAL-COPY-001` uses the callback helper around the existing CLI subprocess and asserts a non-zero exit whose combined `stdout` and `stderr` from the `--json` invocation contains the `z-overlay-copy-failure.sock` basename, plus preservation of the workspace marker. The external Node.js 24 macOS candidate-gate envelope is the final platform proof; no in-tree test substitutes for it.

## DES-M5-CI-005: Platform durability adapter
Responsibilities: Preserve immutable source publication guarantees while classifying only a closed set of unsupported parent-directory sync results by platform.
Interfaces: `flushDirectory()` and `syncSourceDirectory()` in `packages/analysis/src/tdd-source-lfs.ts`; publication sequencing in `packages/analysis/src/tdd-source-storage.ts`; `TEST-M5-CI-WINDOWS-DURABILITY-001` in `tests/tdd-source-windows-durability.test.ts`.
Constraints: Publication order remains write, file flush, authorization, exclusive no-replace link or rename, size/SHA-256 rehash, parent-directory sync and cleanup. The directory adapter catches errors from both directory open and directory `sync()` and receives the operation phase explicitly so no file-level error enters the unsupported branch. POSIX directory-open errors are never tolerated; POSIX tolerates exactly `EINVAL`, `ENOTSUP`, `EISDIR` and `EBADF` from directory `sync()` only. All other errors preserve their current typed source diagnostic. Tests use real Windows publication plus injected phase-specific errors on every platform, assert every POSIX open error remains non-tolerated, assert `EPERM` remains non-tolerated during POSIX sync, and assert `ENOENT` remains fatal for both Windows directory-open and sync paths.

## DES-M5-CI-006: Cross-platform candidate tree comparator
Responsibilities: Compare immutable candidate Git entries with deterministic worktree bytes and verified LFS logical content without conflating unsupported Windows worktree mode bits with Git index identity.
Interfaces: candidate checkout preparation and `compareTrackedTree()` in `packages/analysis/src/workspace-manager.ts`; historical and candidate-head source binding validation in `verifyCandidateLfsClosure()` from `packages/analysis/src/candidate-git-distribution.ts`; candidate workflow checkout/configuration in `.github/workflows/candidate-gate.yml`; `TEST-M5-CI-WINDOWS-TREE-001` in `tests/candidate-tree-portability.test.ts`; `TEST-M5-CI-CANDIDATE-HEAD-ATTRIBUTES-001` in `tests/git-lfs-distribution.test.ts`.
Constraints: Before `actions/checkout`, the workflow runs `git config --global core.autocrlf false`; every programmatic candidate and QA checkout applies the same setting before materialization, and repository attributes preserve LF for authoritative fixtures. After every workspace-local config write and immediately before comparison, the comparator obtains the effective value with `git config --show-origin --get core.autocrlf` and requires the selected value to be `false`. It verifies tracked `.gitattributes` entries against the candidate manifest before classifying other paths. Before attribute evaluation it resolves `git rev-parse --git-path info/attributes`; any existing non-regular or unreadable entry, or a readable regular file with non-whitespace content, fails with `RELEASE_CANDIDATE_TREE_MISMATCH`. It creates one empty comparator-owned regular file outside the candidate worktree, removes `GIT_ATTR_SOURCE` from the child environment, invokes attribute queries with `GIT_ATTR_NOSYSTEM=1`, `git -c core.attributesFile=<empty-file> -c attr.tree= check-attr --cached`, and removes the empty file in a `finally` block after success or failure; therefore system, global, `attr.tree`, environment-selected, info, and unstaged worktree attributes grant no authority, while only verified candidate-index `.gitattributes` content remains effective. It accepts regular non-LFS paths only in one of two explicit classes: text has candidate-index `text` value `set` or `auto` and `eol` value `lf`; binary has candidate-index `text` value `unset`, with EOL attributes and `git ls-files --eol` content tokens ignored for classification. An unspecified `text` value fails. For a text-class path whose exact candidate and worktree bytes contain no CR or LF, including empty and non-empty single-line content, `git ls-files --eol` must report `i/none w/none`; otherwise both exact byte streams must contain LF and no CR and the report must be `i/lf w/lf`. Text-class `i/crlf`, `w/crlf`, `mixed`, `-text`, or mismatched reports fail. A binary-class path may contain LF, CRLF, NUL, or no line ending and may therefore report `lf`, `crlf`, `mixed`, `-text`, or `none`; its acceptance depends on candidate-index `text: unset` plus unconditional exact-byte identity, never on those content tokens. Symlinks and Gitlinks bypass text/EOL classification and retain their existing exact type/target or object-ID comparison. It permits candidate-index `filter=lfs` only for the exact verified LFS source paths; any candidate-index filter on a non-LFS path or any other filter value fails before byte comparison. It always verifies index path, object ID and Git mode against the candidate manifest. For every non-LFS regular file, it reads raw worktree bytes without clean, smudge or working-tree-encoding filters and computes the Git blob object ID from the canonical `blob <length>\0<bytes>` representation; that ID must equal the candidate object ID. LFS files verify pointer identity, logical size, SHA-256 and Git mode before and after the gate. Mode-check policy derives only from `process.platform`: POSIX compares supported worktree executable bits with Git mode regardless of repository config; Windows never reads worktree executable bits regardless of `core.fileMode`, configures `core.fileMode=false` for checkout stability, and still rejects index-mode divergence. The post-gate allowlist remains unchanged. Tests cover empty and non-empty no-newline text, LF-terminated text, hydrated LFS, empty binary, binary LF/CRLF/NUL content, a text-class NUL mismatch, symlink and Gitlink handling, unrelated tracked mutation after hydration, CRLF/mixed conversion, unstaged `.gitattributes`, non-empty/non-regular/unreadable `.git/info/attributes`, global `core.attributesFile`, system attributes, `attr.tree`, `GIT_ATTR_SOURCE`, a late local override, a custom non-LFS filter, raw-byte hashing without filters, comparator empty-file cleanup on success and failure, Windows with both `core.fileMode` values, Windows index-mode divergence, attempted POSIX `core.fileMode=false` bypass and POSIX executable-bit divergence.
Requirements: REQ-M5-CI-006
ADRs: ADR-0042
Depends-On: DES-M5-CI-001 DES-M5-012 DES-M5-023

1. The historical closure scope remains the exact existing namespace `.musubix/evidence/tdd-source/v1/blobs/`; this optimization neither adds nor removes an accepted path class.
