# Node.js 24 GitHub Actions design

## DES-M5-CI-001: Single-version GitHub Actions runtime policy
Responsibilities: Define one authoritative Node.js 24 policy across candidate verification, release, and npm-publish workflows while preserving the published Node.js `>=20` runtime contract.
Interfaces: exported `candidateMatrixJobs`, `historicalCandidateMatrixJobs`, `CandidateGateJob`, `loadCandidateGateResults()`, and `validateCandidateGateSet()`, plus module-private `parseCandidateGateResult()`, in `packages/analysis/src/candidate-gate.ts`; candidate-gate status projection in `packages/cli/src/main.ts`; `.github/workflows/candidate-gate.yml`; `.github/workflows/release.yml`; `.github/workflows/npm-publish.yml`; `package.json` `engines.node`; `README.md`; `README-ja.md`; `docs/migration-guide.md`; `tests/candidate-gate.test.ts`; `tests/candidate-gate-trust.test.ts`; `TEST-M5-CI-NODE24-001` in `tests/candidate-gate.test.ts` verifying `REQ-M5-CI-001` and `REQ-M5-COMPAT-007`; `TEST-M5-CI-HISTORICAL-GATES-001` in `tests/candidate-gate.test.ts` verifying `REQ-M5-RELEASE-002`, including retired-envelope ingestion and public candidate-snapshot status projection.
Constraints: `candidateMatrixJobs` and the candidate-gate workflow matrix each contain exactly `{ os: "ubuntu", nodeMajor: 24 }`, `{ os: "windows", nodeMajor: 24 }`, and `{ os: "macos", nodeMajor: 24 }` once. `TEST-M5-CI-NODE24-001` enumerates every step whose `uses` value identifies `actions/setup-node@<any ref>` by case-insensitive owner/repository comparison under `.github/workflows/*.yml` and `.github/workflows/*.yaml`, requires a non-empty set, rejects a missing `node-version`, accepts a literal only when its scalar string form is exactly `24`, and accepts a matrix expression only when the complete scalar matches `${{ matrix.<key> }}`, the referencing job's `strategy.matrix` contains only a literal, non-empty `include` key, the referenced key is present in every include entry, and its resolved set is exactly `{24}`; it rejects operators, functions, concatenation, missing or dynamic include lists, missing referenced keys, Node.js 20 or 22, and every indirect or non-`include` version source not statically resolvable under that rule. For candidate-gate `matrix.include`, each entry must contain only `runner`, `os`, and `node`; projecting each entry to `{ os, nodeMajor: node }` must equal `candidateMatrixJobs` exactly, and `runner` must map Ubuntu to `ubuntu-latest`, Windows to `windows-latest`, and macOS to `macos-latest`. The candidate matrix job declares exactly one `actions/upload-artifact` step with name `candidate-gate-${{ matrix.os }}-node${{ matrix.node }}`, path `${{ runner.temp }}/candidate-gate-envelope.json`, and `if-no-files-found: error`, binding artifact count and unique names one-to-one to matrix size; release and npm-publish execution remains on their existing operating-system runners. `.github/workflows/candidate-gate.yml` declares `CODE-M5-CI-NODE24-001` implementing `REQ-M5-CI-001` through `DES-M5-CI-001`; the existing release and npm-publish workflow code headers add `REQ-M5-CI-001` to `@implements` and `DES-M5-CI-001` to `@design`; the existing `CODE-M5-CANDIDATE-GATE-001` header in `packages/analysis/src/candidate-gate.ts` likewise adds `REQ-M5-CI-001` and `DES-M5-CI-001`; generated trace files are rebuilt rather than edited so strict implementation coverage and freshness pass. `historicalCandidateMatrixJobs` contains only the four retired identities `{ubuntu,20}`, `{ubuntu,22}`, `{windows,22}`, and `{macos,22}`. `CandidateGateJob` is the union of `candidateMatrixJobs` and `historicalCandidateMatrixJobs` so persisted results and tests require no unsafe casts. `parseCandidateGateResult()` first validates the basic result and job structure independently of accepted identity membership, requiring `job` to be a record with a non-empty string `os` and a positive integer `nodeMajor`, and retains the runtime binding `runtime.os === job.os` plus `runtime.nodeMajor === job.nodeMajor`; it then separately checks the supplied accepted-job set and accepted command sets. Persisted journal parsing passes the seven-identity union plus the existing `[legacyCandidateGateCommands, requiredCandidateGateCommands]`, while new-envelope ingestion passes only `candidateMatrixJobs` plus `[requiredCandidateGateCommands]`; a retired identity during ingestion throws `RELEASE_GATE_EVIDENCE_STALE` before append with a message naming `<os>-node<major>` as outside the current candidate matrix. `loadCandidateGateResults()` is otherwise unchanged: it applies no retired-identity filter and returns the greatest-order record per job identity, so authoritative retired identities remain observable to historical inspection and deletion invalidation. `validateCandidateGateSet()` filters only identities absent from `candidateMatrixJobs` before context, duplication, command-set, status, and missing-job checks; retained Ubuntu/24 records from earlier candidates continue to produce the existing mismatch or stale diagnostics until replaced by current evidence. The CLI candidate-gate status projection filters context-matching records to `candidateMatrixJobs`, and that filtered set governs both entry into gate classification and current-job failure classification; `TEST-M5-CI-HISTORICAL-GATES-001` asserts retired-only records project `candidateGateStatus: missing` and a complete current matrix containing a current non-pass record projects `candidateGateStatus: fail`. The four retired files under `.musubix/evidence/release/gates/` are retained and not rewritten or deleted; `ubuntu-node24.json` is current evidence and is overwritten by new ingestion. Candidate artifact names continue deriving from OS and Node major and therefore become `candidate-gate-ubuntu-node24`, `candidate-gate-windows-node24`, and `candidate-gate-macos-node24`. Trust-path fixtures use a current Node.js 24 identity; retired-identity ingestion rejection is asserted separately by `TEST-M5-CI-HISTORICAL-GATES-001`. `package.json` remains `engines.node: ">=20"`; the pinned musubix3 `CI compatibility`, `runtime`, and `package runtime range` entries remain byte-unchanged, while the separate `musubix5 verification matrix` entry is updated. README documentation states the Node.js 24 CI policy, the deliberate absence of continuous Node.js 20/22 coverage, and one opaque envelope artifact per candidate-matrix job, currently exactly three, in both English and Japanese lifecycle passages. ADR-0020, the migration-guide intentional-difference entry, and `TEST-M5-CI-NODE24-001` satisfy `REQ-M5-COMPAT-007` governance for the reduced continuously verified Node.js set. The migration guide also documents retired-identity read compatibility and ingestion rejection, possible historical `candidateGateStatus: missing`, and the need for in-flight candidates to rerun gates.
Requirements: REQ-M5-RELEASE-002 REQ-M5-CI-001 REQ-M5-COMPAT-007
ADRs: ADR-0020

## DES-M5-CI-002: Bounded Unix-socket test fixture
Responsibilities: Provide a POSIX-only callback fixture that binds the parallel-runtime overlay-copy failure socket through a short unique alias while placing the real socket entry inside the fixture repository, and remove the temporary candidate-workflow environment workaround once the fixture is self-contained.
Interfaces: `createShortSocketDirectory(base = '/tmp')` and `withShortUnixSocket(targetDirectory, callback, base = '/tmp')` in `tests/fixtures/short-unix-socket.ts`; `ShortUnixSocketContext` containing `socketPath`, `targetSocketPath`, and `shortDirectory`; `TEST-M5-CI-SHORT-SOCKET-PATH-001` in `tests/short-unix-socket.test.ts`; `TEST-M5-CI-DEFAULT-TMPDIR-001` and `TEST-M5-CI-NODE24-001` in `tests/candidate-gate.test.ts`; `TEST-M5-PARALLEL-WORKSPACE-PARTIAL-COPY-001` in `tests/parallel-release-blockers-generation5.test.ts`; the `Run closed verification matrix` step in `.github/workflows/candidate-gate.yml`.
Constraints: `createShortSocketDirectory()` calls `mkdtempSync(join(base, 'm5s-'))`, returns a newly created mode-0700 directory, and wraps creation failure in an error that names `base`; normal callers omit the `base` test seam. `withShortUnixSocket()` rejects Windows before mutation, computes `<shortDirectory>/target/z-overlay-copy-failure.sock`, and rejects a UTF-8 pathname longer than 90 bytes before creating the directory symlink or calling `listen()`, removing the unique directory before propagating the length error. For a bounded path it creates the `target` directory symlink pointing to the caller's existing target directory and binds through that symlink; `targetSocketPath` is exactly `join(targetDirectory, 'z-overlay-copy-failure.sock')`. It creates and owns the `node:net` server, attaches both `listening` and `error` handling before `listen()`, rejects bind errors with the path and byte length, invokes the async callback exactly once only after listening, and in `finally` closes only a started server, waits for `close` when applicable, tolerates the socket entry already being absent after close, removes a remaining entry through `targetSocketPath` only when this server reached `listening` and the entry is a socket, then recursively removes only its exact unique short directory without traversing the `target` directory symlink. Cleanup covers callback success, callback failure, bind failure, and overlength rejection; it is idempotent and preserves and rethrows the callback, bind, or length error unless cleanup itself is the only failure. A pre-existing non-socket target entry survives bind failure. The module imports neither `node:os` nor application code and reads no temporary-directory environment variables. The `CODE-M5-CI-SHORT-SOCKET-001` annotation contains `@implements REQ-M5-CI-002` and `@design DES-M5-CI-002` but no `@verifies`; the existing candidate-workflow `CODE-M5-CI-NODE24-001` annotation adds `REQ-M5-CI-002`; test annotations remain separate so strict trace classifies implementation and test evidence independently. `TEST-M5-CI-SHORT-SOCKET-PATH-001` runs platform-independent source checks everywhere; on Windows it asserts early rejection, while on POSIX it uses two helper invocations to prove uniqueness, verifies mode and byte bound, derives and later removes a controlled base with one padding component whose length is `max(1, 91 - Buffer.byteLength(join(resolvedParent, 'm5s-XXXXXX', 'target', 'z-overlay-copy-failure.sock'), 'utf8'))`, keeps that component at most 255 bytes, asserts the resulting candidate is longer than 90 bytes, then proves reachable length rejection and unique-directory cleanup; it observes the real target socket entry while listening, provokes a handled bind error with a pre-existing non-socket entry and proves that entry survives, forces a callback failure and proves that the same error is rethrown after cleanup, confirms a sentinel and target directory survive, and invokes `createShortSocketDirectory()` with a missing-parent base to verify the diagnostic. `TEST-M5-CI-NODE24-001` stops requiring the positive `TMPDIR` expectation while retaining its Node.js, matrix, artifact, documentation, and compatibility assertions. `TEST-M5-CI-DEFAULT-TMPDIR-001` verifies `REQ-M5-CI-002` and asserts across the whole workflow document that no `env` mapping assigns `TMPDIR` and no command writes `TMPDIR` to `GITHUB_ENV`; this prohibition is workflow-scoped and does not forbid a focused subprocess test from setting `TMPDIR` to construct a deliberate cross-filesystem fixture. `TEST-M5-PARALLEL-WORKSPACE-PARTIAL-COPY-001` uses the callback helper around the existing CLI subprocess and asserts a non-zero exit whose combined `stdout` and `stderr` from the `--json` invocation contains the `z-overlay-copy-failure.sock` basename, plus preservation of the workspace marker. The external Node.js 24 macOS candidate-gate envelope is the final platform proof; no in-tree test substitutes for it.
Requirements: REQ-M5-CI-002
ADRs: ADR-0022
Depends-On: DES-M5-CI-001 DES-M5-PARALLEL-004 DES-M5-PARALLEL-007
